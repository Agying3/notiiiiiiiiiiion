## 一、已确认的事实（有抓包或请求为证）

### 1. 域名与入口链路

| 入口 | 行为 |
| --- | --- |
| `https://www.notion.com/signup` | **307** 跳 `https://app.notion.com/signup` |
| `https://www.notion.so/signup` | 302 跳 `app.notion.com/signup` |
| `https://www.notion.so/login` | 302 跳 `app.notion.com/login` |
| `https://www.notion.com/` | 200，营销站，带 `__NEXT_DATA__` |

真正的产品/API 主机是 **`app.notion.com`**，`www` 只是外壳。

### 2. 直连不可用，必须走代理（重要）

| 目标 | 直连结果 | 住宅代理结果 |
| --- | --- | --- |
| `POST app.notion.com/api/v3/ping` | 25s 超时 | 200，1.3~2.8s |
| `GET app.notion.com/_assets/6793-*.js`（118KB） | `SSLError: Recv failure: Connection was reset` | 200，0.26~1.5s |
| `GET app.notion.com/signup` | `SSL_connect: Connection closed` | 200，20KB |

**结论**：直连时页面永远卡在 loading 转圈（截图 `screenshot-headful-signup.png` 为证，body 为空）。换住宅代理后表单立即正常渲染（`signup-via-proxy.png`）。所以「换 IP」不是可选优化，是**前置必要条件**。

### 3. 前端启动时序（未登录态，注册页）


固定请求头（缺了会被按旧客户端处理）：

```

Notion-Audit-Log-Platform: web
Content-Type: application/json
```
`getAppConfig` 还要求 `clientSdkApiKey: client-Tgza5wNFa8dVt9BdeUfG6Vkm29bHxX10MhoztTMzLBB`（页面内公开常量）。

`getAppConfig` 返回里含 `statsigUser.custom.country`，**服务端按出口 IP 判地域**（直连判到 JP，代理判到对应国家），可控。

### 4. 注册第一步：邮箱判定接口

用户填完邮箱按回车，前端只发一个请求：

```
POST https://app.notion.com/api/v3/getLoginOptions
{"email":"<MAIL>","requireWorkTypeEmail":false}
```

返回结构：

```json
{
  "hasAccount": true,
  "samlSignIn": "unavailable",
  "passwordSignIn": false,
  "mustReverify": false,
  "loginOptionsToken": "[REDACTED_NOTION_TOKEN]",
  "authFlowId": "<uuid>"
}
```

实测 4 组不同邮箱（随机 gmail / qq / 已知不存在域名 / 老邮箱）**全部返回 `hasAccount: true`**。
→ 该接口**不能用来判断邮箱是否已注册**，注册/登录分流在拿到 `loginOptionsToken` 之后的下一步才真正决定；token 与 `authFlowId` 是后续步骤的绑定凭证，必须原样带回。

### 5. 注册的真实卡点是 hCaptcha（invisible）

提交邮箱后 DOM 立刻注入：

```
<iframe src="https://newassets.hcaptcha.com/captcha/v1/.../hcaptcha.html#frame=challenge
  &sitekey=<uuid>&size=invisible&host=app.notion.com">
<textarea name="h-captcha-response">  ← 空
```

- 类型：**hCaptcha invisible（无感）**，不是 Turnstile，不是 reCAPTCHA
- sitekey：`<uuid>`
- 提交邮箱后页面卡在 `Loading...`，说明这一步的响应在等 captcha token

这就是「注册流程必须能出 captcha token」的技术原因，也是后续所有方案的分水岭。

### 6. 未登录态的鉴权边界

| 请求 | 未登录返回 |
| --- | --- |
| `POST /api/v3/getSpaces` | **401** `UnauthorizedError` / `Must be authenticated.` |
| `POST /api/v3/loadCachedPageChunkV2` | 400 `ValidationError` |
| `POST /api/v3/getPublicPageData`（假 blockId） | 500 `MemcachedCrossCellError` |

**有用法**：内部 v3 接口「不存在」返回 404，「存在但参数/权限不对」返回 400/401/500。可以据此批量确认端点是否存在——这是枚举隐藏注册接口的可靠指纹，比看 JS 更快（压缩后的 bundle 里只搜到 1 个 `/api/v3/authValidate` 字面量，说明接口名是拼接或混淆的）。

## 二、官方 API 侧（`developers.notion.com`，已核对原文）

- **最新 API 版本：`2026-03-11`**（`Notion-Version` 头必填，否则按旧契约解析）
- 三种凭证模型：
  1. **Internal connection token**（`secret_...` / `ntn_...`）——单工作区，静态
  2. **Public connection OAuth 2.0**——多工作区，用户授权页面
  3. **PAT（personal access token）**——用户级，走本人权限，页面无需单独分享
- **限流**（这是自动化脚本必须实现的）：
  - 每连接：Business/Enterprise **600 req/min**；其他套餐 **180 req/min**
  - 另有全工作区共享额度，`Retry-After` 可能 >60s
  - `additional_data.rate_limit_reason` 区分是哪一层限流；`public_api_request_blocked` = 连接被禁，重试无用
  - 429/529 必重试；500/502/503/504 仅在幂等请求（GET/DELETE）重试
  - **写请求返回 503 时不要盲目重试**——可能已落库，读 `additional_data.retry_guidance`
- **体积限制**：单请求 ≤1000 block、≤500KB；富文本 content ≤2000 字符；URL ≤2000；relation/people/multi_select 单次 ≤100
- **数据模型（2025-09-03 之后的分水岭）**：
  `database` → `data_sources[]` → `page`
  属性 schema 在 **data_source** 上，`database.properties` 已废弃；建页要用 `parent.data_source_id`
- 官方还提供了：`llms.txt` 全量文档索引、`ntn` CLI、Notion MCP（含 MCP 工具限流 `mcp_tool_rate_limit`）、Workers、Admin API（含 SIEM/审计日志、法律保留、PAT 吊销）、Agents beta、Agent Skills

## 三、当前判断

1. **技术主线成立**：HTTP 复现注册链路的方向没问题，唯一硬门槛是 **hCaptcha invisible 的 token**，不是 Notion 自身逻辑。
2. **代理是刚需**：直连连静态资源都 RST，谈不上注册。（代理池 250 条已实测 5 条全部 200，可用）
3. **指纹维度确实存在**：`browserId / deviceId / stableID / clientSdkApiKey / country` 都进 `getAppConfig`，服务端按这几个维度做风控画像——这正是 CloakBrowser「一指纹一 IP + seed 派生」能对上号的地方。
4. **不要指望 `getLoginOptions` 做账号探测**，它恒真。
